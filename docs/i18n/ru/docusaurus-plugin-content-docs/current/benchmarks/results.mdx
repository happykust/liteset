## Что показывают цифры

Четыре метрики вместе рассказывают одну историю: **перенос веб-слоя с pre-forked Flask-процессов на единый ASGI event loop меняет cost model деплоя Superset.**

- **Throughput (RPS).** Liteset обслуживает больше запросов в секунду на том же железе, потому что async-обработчики не блокируются на I/O. Пока один запрос ждёт ответ от аналитической БД, тот же воркер обслуживает другие.
- **p95 latency.** Хвостовая задержка падает, потому что запросы перестают стоять в очереди за заблокированными воркерами. Нет жёсткого предела `WORKERS × THREADS`.
- **Resident memory.** Один Uvicorn-процесс заменяет N pre-forked Gunicorn-воркеров, каждый из которых нёс свою копию Python-интерпретатора, реестра SQLAlchemy и пула соединений.
- **Sustained concurrency.** Без потолка на per-process пул соединений Liteset держит больше одновременных подключений без деградации.

## Оговорки

- Это **макро-бенчмарки**. Они измеряют end-to-end поведение бэкенда, а не скорость конкретного SQLAlchemy-запроса или роутины рендера графика.
- Нагрузки, в которых доминирует **latency аналитической БД** (например, тяжёлые агрегации в ClickHouse), покажут меньшую дельту — узкое место downstream, а не в Superset.
- Поведение фронтенда **идентично** by design; ничто на этих графиках не измеряет время рендера.
